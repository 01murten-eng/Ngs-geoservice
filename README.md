# Геосервис отчётности по работам ДЗЗ (ГСР-50)

Открытый геопортал для отчёта о ходе работ по дистанционному зондированию
земли в рамках геологической съёмки ГСР-50 (ГДП-50, ГГК-50, ГМК-50). Показывает
карту участков, окрашенных по статусу выполнения, ключевые показатели и
статус актирования по 5 этапам. Ссылку можно отправлять руководству — вход
не требуется, сайт полностью статический.

**Демо:** после публикации через GitHub Pages сайт будет доступен по адресу
вида `https://<ваш-логин>.github.io/<название-репозитория>/`.

## Как это устроено

- **Границы участков** — файл `data/sites.geojson`. Загружается один раз и
  меняется редко (только если меняется состав или контуры участков).
- **Контур Казахстана и границы областей** — `data/kz_country.geojson` и
  `data/kz_regions.geojson`, справочный фон карты. Источник — Natural Earth
  (общественное достояние, атрибуция не требуется). Обновлять не нужно.
- **Реестр участков и статус этапов** — две вкладки в Google Таблице,
  опубликованные как CSV-ссылки. Сайт подтягивает их при каждом открытии —
  никакой пересборки или git-коммитов для обновления цифр не нужно. Статус
  и % выполнения каждого участка сайт сам считает по статусам его 5 этапов —
  отдельно их вводить не нужно.
- **Сайт** — обычные HTML/CSS/JS без сборки: Leaflet (карта), Chart.js
  (график), PapaParse (чтение CSV).
- **ТЗ участков** — исходные файлы лежат в `data/tz/`, ссылка на нужный файл
  прописана в колонке `tz_link` листа Sites и открывается по кнопке в попапе
  на карте. Часть файлов охватывает сразу несколько участков (например, один
  документ на 4, 5 и 6 участки) — это реальные документы «как есть», в них
  просто несколько приложений подряд.

Проект сейчас содержит **реальные стартовые данные**: 19 участков (участок
13 исключён по вашему указанию), их настоящие границы, исполнители и
регионы — из загруженных ТЗ и официальной таблицы распределения
(`data/sites.geojson`, `data/sites.csv`, `data/stages.csv`).

**Важно про локальный просмотр:** браузеры блокируют загрузку локальных CSV
и GeoJSON при открытии `index.html` напрямую двойным щелчком (протокол
`file://`). Чтобы посмотреть сайт на своём компьютере, запустите в папке
проекта простой локальный сервер, например:

```
python3 -m http.server 8000
```

и откройте `http://localhost:8000`. На GitHub Pages эта проблема не
возникает — там сайт открывается по обычному `https://`.

**Площадь участка 15 не заполнена:** в файле «центр_крайний» (где, по всей
видимости, должно было быть его ТЗ) он не упоминается — файл заканчивается
на Приложении 3. Регион взят из официальной таблицы распределения
(Павлодарская/Абай/Карагандинская), площадь — впишите в `data/sites.csv`
вручную, когда найдётся документ.

## Как считается статус и % участка

Отдельного поля «% выполнения» вводить не нужно — сайт считает его сам по
статусам 5 этапов участка в `data/stages.csv`:

- % = (число актированных этапов / 5) × 100.
- «Завершено» — все 5 этапов актированы.
- «Проблема» — хотя бы один этап просрочен (дедлайн прошёл, а акт не
  подписан).
- «В работе» — хотя бы один этап актирован или сдан на актирование.
- «Не начато» — по всем этапам ничего не сдано.

## Настройка своих данных

### 1. Создайте Google Таблицу с двумя листами

**Sites** — реестр участков (заполняется один раз, редактируется редко):

| site_id | name | executor_type | executor_name | region | planned_area_km2 | planned_start | planned_end | tz_link | note |
|---|---|---|---|---|---|---|---|---|---|
| S01 | Участок №1 | НГС | Абдулхаир Р. | Ұлытау | 5127 | | | ссылка на ТЗ | |
| S04 | Участок №4 | Подрядчик | ТОО «Институт геологических наук им. К.И. Сатпаева» | Ұлытау | 5894 | | | ссылка на ТЗ | |

- `site_id` должен совпадать со свойством `site_id` соответствующего полигона
  в `data/sites.geojson`.
- `executor_type` — строго `НГС` или `Подрядчик` (используется для группировки
  в статистике). `executor_name` для участков НГС — имя ответственного
  геолога, для подрядчиков — название компании.
- `region` необязателен, но если заполнен — показывается в попапе на карте.
- `note` — свободное текстовое примечание к участку, для ручных заметок
  (кто фактически выполнял этап, особенности и т.п.). Показывается в попапе
  на карте, если заполнено.
- `status_override` — необязательное ручное переопределение статуса участка:
  `план`, `в работе`, `завершено` или `проблема`. Если заполнено — сайт
  показывает именно этот статус (и, соответственно, цвет на карте и место в
  фильтре), независимо от того, что получается по автоматическому расчёту
  из этапов. Так можно вручную перенести участок между колонками
  «Проблемные» / «В работе» / «Завершено» по своему усмотрению. Оставьте
  пустым, чтобы статус считался автоматически.

**Stages** — статус актирования по 5 этапам (дедлайны — 24.08, 24.09, 24.10,
24.11, 10.12.26 — общие для всех участков и заданы один раз в
`js/config.js` → `STAGE_DEADLINES`, здесь их менять не нужно):

| site_id | stage | status | act_date | comment | report_link | percent |
|---|---|---|---|---|---|---|
| S01 | 1 | актирован | 2026-08-24 | | data/acts/act_S01_stage1.docx | 100 |
| S16 | 2 | подготовлен | | | | 45 |
| S07 | 1 | не начат | | | | |

- `status` — один из трёх вариантов: `не начат`, `подготовлен` (сдан на
  актирование, акт ещё не подписан), `актирован` (акт подписан, оплата
  прошла). Если дедлайн этапа прошёл, а статус не «актирован» — сайт сам
  подсвечивает участок как просроченный, отдельно отмечать это не нужно.
- `percent` — ваша ручная оценка % выполнения именно этого этапа (0–100),
  например «сняли 45% сцен по этапу 2». Для этапа со статусом «актирован»
  этот столбец не важен — сайт всегда считает такой этап как 100%, что бы
  здесь ни было написано. Общий % участка наверху — среднее по всем 5 этапам.
- `act_date` заполняется только при статусе «актирован» — эта дата попадает
  на график динамики внизу страницы.
- `report_link` — ссылка на отчёт/акт по этапу (необязательно). Файлы уже
  сданных отчётов лежат в `data/acts/`; в попапе на карте появляется кнопка
  «Открыть отчёт по этапу N →» на самый свежий актированный этап, у которого
  есть ссылка.
- Для удобства ввода добавьте в Google Таблице проверку данных (Данные →
  Проверка данных → список значений) на колонку `status`, чтобы избежать
  опечаток.
- Каждую неделю обновляйте только те строки, где реально что-то изменилось —
  остальные так и остаются «не начат» до своего часа.

### 2. Опубликуйте оба листа как CSV

Файл → «Опубликовать в интернете» → выберите лист (Sites или Stages) →
формат «Значения, разделённые запятыми (.csv)» → Опубликовать. Повторите для
второго листа. Скопируйте обе ссылки.

### 3. Подставьте ссылки в `js/config.js`

Замените значения `SITES_CSV_URL` и `STAGES_CSV_URL` на полученные ссылки.

### 4. Замените границы участков

Подготовьте `data/sites.geojson` с реальными полигонами участков, если
состав участков изменится. У каждого полигона (`properties`) обязательно
должно быть поле `site_id`, совпадающее с реестром Sites.

### 5. Разместите на GitHub Pages

1. Создайте репозиторий на GitHub, загрузите в него содержимое этой папки.
2. Settings → Pages → Source: ветка `main`, папка `/root`.
3. Через минуту сайт появится по ссылке из настроек Pages.

## Еженедельная рутина

Каждую неделю: откройте лист **Stages**, обновите статус тех этапов, где
что-то изменилось (сдан на актирование / акт подписан) — сайт обновится сам
при следующем открытии ссылки, ничего пересобирать не нужно.
